# MU Link — протокол канала Mac Utils ↔ Mac Utils Share (ПК)

Источник истины для обеих сторон. Файл одинаковый в ветках `development` (Mac, модуль `MULink`) и `windows`
(`windows/link/`). Общие тестовые векторы — `Tests/Fixtures/mu-link/vectors.json` (тоже одинаковый в обеих ветках):
обе стороны в тестах проверяют по нему подписи, доказательства кода и разбор кадров.

Версия протокола — **1**. Меняется только добавочно (как протокол share): новые поля и новые типы сообщений не ломают
старую сторону.

## 1. Транспорт

- **WebSocket поверх TCP**, без TLS: `ws://<адрес ПК>:47130/mu-link`.
  - Порт **47130**. Не занят ничем известным: Sunshine/Moonlight — 47984–48010, Tailscale — 41641/udp.
  - Шифрование и подлинность узлов даёт Tailscale (WireGuard). Но подключиться может любой узел tailnet,
    поэтому у канала своя проверка: сопряжение кодом и подписи ключей устройств при каждом подключении.
- **Слушает только ПК, Mac только подключается.** Слушающий сокет на Mac вызвал бы окно брандмауэра macOS.
- **ПК слушает только на адресах Tailscale:**
  - IPv4 `100.64.0.0/10`, IPv6 `fd7a:115c:a1e0::/48` — по одному сокету на адрес. Не `0.0.0.0`.
  - Адреса перечитываются раз в 30 с: Tailscale мог подняться позже Share.
  - Входящее соединение с адреса вне этих сетей закрывается сразу.
  - Windows один раз спросит разрешение брандмауэра для Mac Utils Share. Достаточно «Частные сети»: Tailscale —
    частная сеть.
- **Mac** знает адрес ПК из настроек «Windows-ПК». По умолчанию — адрес хоста из Moonlight; можно ввести
  IP Tailscale или имя MagicDNS.

## 2. Кадры

- **Текстовые кадры — JSON-объект** `{ "v": 1, "type": "...", "id": "...", ... }`:
  - `v` — версия протокола отправителя;
  - `type` — тип сообщения;
  - `id` — строка до 64 символов, уникальная у отправителя. `pong` повторяет `id` своего `ping`.
- **Правила разбора:**
  - **Незнакомый `type` молча игнорируется**, связь не рвётся. Незнакомые поля тоже игнорируются.
  - Не JSON, не объект, нет `type` или кадр больше 1 МиБ → `error` `protocol` и закрытие 4400.
- **Версии.** В `hello` каждая сторона сообщает свою `v`; дальше обе говорят на `min(v_mac, v_pc)`. Версия ниже 1 →
  `error` `bad-version`, закрытие 4400.
- **Двоичные кадры** — для будущей передачи файлов (§7). В версии 1 не отправляются; полученный двоичный кадр
  игнорируется.

## 3. Ключи устройств

- Ed25519, публичный ключ — 32 байта в base64url без `=` (43 символа), подпись — 64 байта в base64url (86 символов).
- **Mac:** ключ трансляции `ShareIdentity` (`Sources/MUScreenShare/ShareIdentity.swift`). Это тот же ключ, что
  подписывает share v2 у relay. Подписываются только строки с доменом `mu-link/1`, поэтому подпись MU Link нельзя
  выдать за подпись share, и наоборот.
- **ПК:** свой ключ Mac Utils Share. Создаётся при первом запуске канала, лежит в профиле пользователя:
  `%APPDATA%\Mac Utils Share\mu-link-identity.json`.
- **Отпечаток** для показа человеку: первые 8 байт SHA-256 публичного ключа, `a1b2-c3d4-e5f6-0718` (как у share).

**Канонические строки** (UTF-8, поля через `\n`, без завершающего `\n`):

```
mu-link/1\n<kind>\n<macPub>\n<pcPub>\n<clientNonce>\n<serverNonce>
```

| `kind` | Кто | Чем | Зачем |
|---|---|---|---|
| `server` | ПК | подпись Ed25519 ключом ПК | ПК владеет `pcPub` и ответил именно на этот `hello` |
| `client` | Mac | подпись Ed25519 ключом Mac | Mac владеет `macPub` и видел этот ответ ПК |
| `pair-mac` | Mac | HMAC-SHA256, ключ — 6 цифр кода (UTF-8) | при сопряжении: Mac знает код |
| `pair-pc` | ПК | HMAC-SHA256, ключ — 6 цифр кода (UTF-8) | при сопряжении: ПК знает код |

Nonce — 32 случайных байта в base64url, новые на каждое подключение. В подписи входят оба ключа и оба nonce:
подпись нельзя повторить в другом подключении или переслать другому устройству.

## 4. Рукопожатие (каждое подключение)

```
Mac → ПК  hello  {role:"mac", app, version, name, caps, pub:macPub, nonce:clientNonce}
ПК  → Mac hello  {role:"pc",  app, version, name, caps, pub:pcPub,  nonce:serverNonce, paired, sig:sign_pc(server)}
Mac → ПК  auth   {sig: sign_mac(client)}            — обычное подключение
          pair   {proof: HMAC(code, pair-mac), sig: sign_mac(client)}   — сопряжение
ПК  → Mac paired {proof: HMAC(code, pair-pc)}      — только после pair
ПК  → Mac ready  {}
ПК  → Mac status {…}
```

**Mac, получив `hello` ПК:**
- проверяет `sig`;
- если пара уже есть — требует `pub` ПК равным сохранённому. Иначе — «На этом адресе другой ПК», закрытие 4401,
  повтор по обычному расписанию;
- `paired: false` при сохранённой паре означает, что ПК забыл этот Mac: состояние «ПК не знает этот Mac —
  свяжите заново», без повторов.

**ПК, получив `auth`:**
- ключ Mac есть в списке связанных и подпись верна → `ready` и сразу `status`;
- иначе → `error` `unknown-key` или `bad-signature`, закрытие 4401.

**Таймауты и замены:**
- рукопожатие должно закончиться за 10 с, иначе закрытие 4408;
- новое подключение того же Mac закрывает старое с кодом 4409.

## 5. Сопряжение (один раз)

1. **ПК.** В трее — «Связать с Mac…». Открывается окно с кодом из 6 цифр (`crypto.randomInt`), код живёт 2 минуты.
   Пока окно открыто, принимаются сообщения `pair`.
2. **Mac.** Настройки → «Windows-ПК» → «Адрес ПК» (по умолчанию из Moonlight) и «Код с ПК» → «Связать».
   Mac подключается, получает `hello` ПК и проверяет его подпись. Затем первым отправляет `pair`:
   доказательство кода и подпись своим ключом.
3. **ПК проверяет:**
   - окно сопряжения открыто и не заблокировано;
   - доказательство кода верно;
   - подпись Mac верна.

   Если всё так — сохраняет ключ и имя Mac, отвечает `paired` со своим доказательством кода, затем `ready` и
   `status`, окно на ПК показывает «Связан с <имя Mac>».
4. **Mac** проверяет доказательство ПК и сохраняет: адрес, ключ ПК, имя ПК.

**Ограничения:**
- **5 неверных кодов** — код сгорает, приём `pair` блокируется на 5 минут. Ответы:
  - `error` `bad-code` с `attemptsLeft`;
  - после пятой ошибки — `pairing-blocked` с `retryAfter` (с).
- **Нет открытого окна** → `pairing-closed`. На любую ошибку сопряжения — закрытие 4403.

**Почему без SPAKE.**
- Код живёт 2 минуты, попыток 5, канал уже зашифрован WireGuard.
- Первым доказательство отправляет Mac, и только узлу по адресу, который ввёл пользователь, после проверки
  подписи этого узла.
- ПК раскрывает своё доказательство только тому, кто уже доказал код. Значит, посторонний узел tailnet, который
  подключится к ПК, ничего не узнает о коде.

**Забыть пару:**
- Mac — «Забыть ПК»;
- ПК — «Забыть связанные Mac» в окне сопряжения;
- после этого нужно связать заново.

## 6. Сообщения версии 1

| Тип | Кто | Поля | Когда |
|---|---|---|---|
| `hello` | оба | `role` (`mac` \| `pc`), `app`, `version`, `name`, `caps` (массив строк, сейчас пуст), `pub`, `nonce`; у ПК ещё `paired`, `sig` | первым после открытия |
| `auth` | Mac | `sig` | вместо `pair`, если пара есть |
| `pair` / `paired` | Mac / ПК | `proof`, у `pair` ещё `sig` | §5 |
| `ready` | ПК | — | канал готов |
| `ping` / `pong` | оба | `t` — время отправителя `ping`, мс (в `pong` — то же) | Mac шлёт `ping` раз в 5 с, ПК отвечает сразу |
| `status` | ПК | `name` (`os.hostname()`), `os` (`Windows <версия ядра>`), `uptime` (с, `os.uptime()`), `app`, `version` (Share), `power` | после `ready`, раз в 30 с и при изменении |
| `error` | оба | `code`, `message` (для человека), иногда `attemptsLeft`, `retryAfter` | перед закрытием или как ответ |

**`power`** — `{ "source": "ac" | "battery" | "unknown", "percent": 0…100 | null, "minutesLeft": int | null }`.
В версии 1 всегда `{"source":"unknown","percent":null,"minutesLeft":null}`: данные ДБЖ — отдельная задача.

**Коды `error`:**
- `protocol`, `bad-version`;
- `unknown-key`, `bad-signature`;
- `pairing-closed`, `bad-code`, `pairing-blocked`;
- `replaced`, `timeout`.

**Коды закрытия WebSocket:**

| Код | Когда |
|---|---|
| 1000 | обычное закрытие |
| 4400 | ошибка протокола |
| 4401 | ключ или подпись |
| 4403 | сопряжение |
| 4408 | таймаут |
| 4409 | заменено новым подключением |

**Пульс:**
- ни одного кадра 15 с — сторона считает связь потерянной: ПК закрывает соединение, Mac переподключается;
- отклик в настройках Mac и в трее ПК — время `ping → pong`.

## 7. Двоичные кадры (будущее: файлы; в версии 1 не реализованы)

**Управление — текстовыми сообщениями** (появятся в `caps` как `"files"`):

| Сообщение | Поля | Смысл |
|---|---|---|
| `file-offer` | `file` (UUID), `name`, `size`, `sha256`, `mime` | отправитель предлагает файл |
| `file-accept` | `file`, `offset` | получатель принимает; `offset` > 0 — докачка с этого байта (он хранит недокачанное по `sha256` + `size`) |
| `file-ack` | `file`, `offset` | подтверждение каждые 4 МиБ; без него отправитель держит не больше 16 МиБ в полёте |
| `file-done` | `file` | получатель сверил `sha256` |
| `file-cancel` | `file`, `reason` | любая сторона |

**Двоичный кадр** — заголовок 28 байт и данные:

| Байты | Поле |
|---|---|
| 0–1 | `0x4D 0x4C` («ML») |
| 2 | версия формата, `1` |
| 3 | вид: `1` — кусок файла |
| 4–19 | UUID передачи, 16 байт |
| 20–27 | смещение куска в файле, uint64 big-endian |
| 28… | данные, до 256 КиБ |

**Обрыв во время передачи.** После переподключения отправитель повторяет `file-offer`, получатель отвечает
`file-accept` с тем смещением, до которого у него всё записано.

## 8. Обрывы и переподключение (Mac)

- Пауза перед повтором: **1, 2, 5, 10, 30, 30, … с**. Счётчик сбрасывается после `ready`.
- Пробуждение Mac или смена сети — повтор сразу.
- Когда ПК вернулся (свет, перезагрузка), связь поднимается сама при очередном повторе, без действий пользователя.
- **Не повторяем** до действия пользователя:
  - ПК не знает этот Mac (`paired: false` или `unknown-key`);
  - пары нет.

**Состояния на Mac:**
- «нет пары»;
- «подключаюсь»;
- «на связи» (отклик, мс);
- «нет связи» (причина: ПК не отвечает, другой ПК на адресе, ПК не знает этот Mac, ошибка протокола);
- во время сопряжения — «связываю».

## 9. Совместимость (проверяется тестами)

- Векторы `Tests/Fixtures/mu-link/vectors.json`:
  - ключи из `macSeed` / `pcSeed` дают `macPub` / `pcPub`;
  - канонические строки совпадают байт в байт;
  - подписи и доказательства из файла проходят проверку на обеих сторонах;
  - все кадры из `frames` разбираются;
  - кадр `future` (`v: 2`, незнакомый тип) игнорируется без разрыва.
- Mac-тесты гоняют клиент против двойника ПК на Swift. Windows-тесты (`node --test`) гоняют сервер против
  двойника Mac на Node. Двойники следуют этому файлу.
